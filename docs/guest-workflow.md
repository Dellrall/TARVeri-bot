## 1. Guest Entry Options

Guests join via the persistent Gateway Panel (`/admin panel`) in the welcome channel:

- **With Referral Code**: Enter a single-use referral code generated by a verified student (`/referral generate`).
- **Direct Application**: Apply directly by submitting their full name, affiliation, and purpose of joining.

## 2. Double Verification Review Process

```mermaid
sequenceDiagram
    autonumber
    actor Guest as Applicant
    actor Student as Referring Student
    actor Admin as Server Staff
    participant Bot as TARVeri Bot
    participant Channel as Private Review Thread

    Guest->>Bot: Submit Guest Application / Referral Code
    Bot->>Channel: Spawn Review Thread (#A0001) & Tag Student
    Student->>Channel: Click [Confirm Vouch] with statement
    Bot->>Channel: Tag Staff Reviewers (Batch of 2)
    alt Approved
        Admin->>Channel: Click [Approve Guest]
        Bot->>Guest: Assign Guest(Approved) Role & Archive Thread
    else Rejected / Expelled
        Admin->>Channel: Click [Reject / Veto] (Kicks user)
        Bot->>Guest: DM Rejection Notice & Kick
    else Manual Close (No Kick)
        Admin->>Channel: Click [Close Ticket] / Run /admin close_ticket
        Bot->>Channel: Lock & Archive Thread (User remains in server)
    end
```

## 3. Alphanumeric Ticket Tracking

Guest review threads and audit records use alphanumeric sequence numbers:
- `#A0001` through `#A9999`
- Rollover to `#B0001` through `#Z9999` $\to$ `#AA0001`

---

## 4. Intelligent Staff Tagging & Auto-Escalation

1. **Active Staff First**: The bot tags 2 online/active moderators first.
2. **1-Hour Auto-Escalation**: If moderators do not respond within 1 hour, TARVeri automatically escalates by tagging the next batch of admins.
3. **User-Accessible Thread Discovery**: Private threads are spawned in public help channels (`#ask-for-help`, `#support`) where unverified users have view permissions, avoiding admin-locked channel deadlocks.

---

## 5. Automatic Revocation

If a verified guest leaves, is kicked, or is banned, active review tickets are automatically closed and referral codes invalidated in SQLite.

---

## 6. Resilient Thread Resolution & Role Rollback

- **Universal Interaction Thread Resolution**: Resolves target review threads through `_resolve_review_thread` using bot API fetching, ensuring that Discord `InteractionChannel` objects are seamlessly converted into fully interactive threads for message posting, member removal, and archiving.
- **Idempotent Thread Locking**: If staff re-click **`Approve Guest`** on a ticket that was previously approved in SQLite but whose thread remained open, TARVeri detects the resolved state and immediately locks and archives the stranded thread.
- **Role Assignment Rollback Guard**: If bot role hierarchy prevents adding the guest role (`discord.HTTPException: 403 Forbidden`), the ticket status is rolled back to `OPEN` via `reopen_guest_ticket()`. Administrators are notified with clear error diagnostics and can re-attempt approval once the bot role is positioned higher in server settings.
